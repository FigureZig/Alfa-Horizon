# 12. Скоринг: упрощённая модель риска и как она влияет на деньги

Ground truth по скорингу. Место в конвейере — шаг 5 на D1 (после стоп-правил, перед таблицами политики); в коде — реализация порта `RiskModel` (`04_decision_engine.md` §1).
Все баллы, пороги, PD и LGD ниже — **наш дизайн**: параметры версии политики, проверяются на синтетике (§7). Нормы закона здесь не нужны.

## 1. Что требует кейс
- «Скоринг ≠ кредитное решение»: скоринг даёт **оценку риска**, решение принимает политика с учётом продукта, суммы, срока, проверок и ограничений банка (PDF, с. 14).
- Подходы допустимы любые: правила, балльная модель, статистика, рейтинг; «каждому значимому признаку соответствует определённое влияние на итоговую оценку»;
  стабильность и хорошая история уменьшают риск, нагрузка, нестабильность и просрочки — увеличивают (PDF, с. 14).
- Модели проверяют «по способности различать заёмщиков с разным уровнем риска, точности и стабильности» (PDF, с. 14) → §7.
- Эксперты: ML не обязателен, «заглушки достаточно», но банковская сторона и скоринг оцениваются (менторская сессия 20.10.2026).

## 2. Модель: балльная карта с сегментами
- **Сегменты:** ИП (нет бухотчётности — 402-ФЗ ст. 6 ч. 2 п. 1) и ООО/АО (есть ГИР БО). У сегментов разный набор факторов.
- **Балл** = база 600 + сумма баллов по факторам, ограничение 300–900. Бины монотонны: лучше показатель — не меньше баллов.
- **PD** — из балла по стандартной шкале скоркарт: `odds = 15 × 2^((score − 600) / 40)`, `PD = 1 / (1 + odds)` — 600 баллов ≈ 6,3%, каждые +40 баллов вдвое снижают шансы дефолта [P23].
- **Класс риска** по порогам балла → им пользуется политика (§5–6).
- Только для тех, кто прошёл стоп-правила (банкротство, дисквалификация, недоимка выше порога, ликвидация отсекаются раньше, D1 шаг 4).

## 3. Факторы (данные — `09_data_contracts.md`)
| # | Фактор | Как считаем | Бины → баллы | Сегмент |
|---|---|---|---|---|
| F1 | Возраст бизнеса | месяцев с даты ОГРН / ОГРНИП | < 12 → −40 · 12–36 → 0 · 36–60 → +20 · > 60 → +35 (< 6 — стоп политики) | все |
| F2 | Стабильность поступлений | коэффициент вариации месячных поступлений за 12 мес. (банк) | < 0,2 → +40 · 0,2–0,4 → +15 · 0,4–0,7 → −15 · > 0,7 → −45 | все |
| F3 | Тренд поступлений | последние 3 мес. к среднему предыдущих 9 | рост > 10% → +15 · ±10% → 0 · падение 10–30% → −20 · > 30% → −50 | все |
| F4 | Долговая нагрузка | платежи по текущим кредитам `AvgMonthPaymentSum` / средние поступления — **до новой сделки**; потянет ли клиент новый платёж, проверяет кап платёжеспособности (13 §6) | < 15% → +30 · 15–30% → +10 · 30–45% → −25 · > 45% → −60 | все |
| F5 | Просрочки | максимум `PastDepthOfDelayInDay` за 12 мес.; `TwoPaymentsSkipped` | 0 → +40 · 1–5 дн. → +10 · 6–30 → −30 · 31–90 → −80 · пропуск двух платежей → −60 (> 90 — стоп) | все |
| F6 | Кредитный голод | обращения за 30 дн. — информационная часть КИ, доступна без согласия (218-ФЗ ст. 6 ч. 9.1); с согласием — `NumberOfRequests` из отчёта | 0–1 → +10 · 2–4 → 0 · ≥ 5 → −30 | все |
| F7 | Налоговая дисциплина | `ОбщСумНедоим` (ФНС) | 0 → +20 · до порога политики → −10 | все |
| F8 | Прибыльность | `financialResult.current2400` (ГИР БО) | > 0 → +20 · ≤ 0 → −25 · нет отчётности → 0 и флаг | ООО/АО |
| F9 | Обороты через наш банк | поступления на наш счёт / выручка (ГИР БО); у ИП выручки в источниках нет → неизвестно | > 70% → +15 · 30–70% → +5 · < 30% → −10 | все |

Неизвестный фактор (источник недоступен) — 0 баллов и флаг `DATA_MISSING` в трассе; если неизвестен F4 или F5 (БКИ), решение идёт по политике факта (`PROVISIONAL` или `MANUAL`, 07 §4).
До согласия (подбор, оффер K2) неизвестны только F4 и F5: F6 берём из информационной части КИ. Реализация и цифры по миру симулятора — `13_credit_mechanics.md` §5, §8.

## 4. Классы
| Класс | Балл | PD по шкале | Смысл |
|---|---|---|---|
| A | ≥ 700 | ≤ 1,2% | низкий риск |
| B | 640–699 | 1,2–3,2% | ниже среднего |

| D | < 560 | > 11,8% | высокий: авто-оферты нет |

## 5. Как класс превращается в деньги
**Ставка** = ключевая ставка ЦБ [M1] + отраслевой спред [M4 − M3] + **спред за риск**. Спред за риск выводим из ожидаемых потерь, а не задаём на глаз:
`EL = PD × LGD`; спред = EL + 1,5 п.п. на операционные расходы и маржу, округление до 0,5.

| Класс | PD для цены | LGD без обеспечения | EL | Спред за риск |
|---|---|---|---|---|
| A | 1,0% | 50% | 0,5% | 2,0 п.п. |
| B | 2,5% | 50% | 1,25% | 3,0 п.п. |
| C | 6,5% | 50% | 3,25% | 5,0 п.п. |
| D | 20% | 50% | 10% | 11,5 п.п. — только после ручного решения |
С поручительством LGD 40%, с залогом 30% [наш дизайн] → обеспечение снижает EL, и это видно клиенту в «почему так».

**Лимит** = минимум капов политики (обороты, платёжная способность, максимум продукта; 04 §3) × множитель класса: A 1,0 · B 0,85 · C 0,6 · D 0 (авто-лимита нет).

## 6. Одинаковый риск → разные условия по продуктам (PDF, с. 14)
| Класс | Овердрафт | Экспресс без обеспечения | Оборотный | Инвестиционный |
|---|---|---|---|---|
| A | авто | авто | авто до порога полномочий | с залогом, аналитик |
| B | авто | авто, лимит × 0,85 | авто до порога | с залогом и поручителем, аналитик |
| C | авто, лимит × 0,6 | только условно: с поручителем | условно: с поручителем | аналитик |
| D | аналитик | отказ + K3 | аналитик | отказ + K3 |
Эта матрица — таблица политики в базе знаний; оптимизатор оферты (04 §8) выбирает по ней «как просили», «условно» или контрпредложение.

## 7. Проверка модели на синтетике (то, что кейс называет различающей способностью, точностью и стабильностью)
- **Как:** `cd backend && uv run python -m qa.scoring` → [`scoring_validation.md`](scoring_validation.md). Портфель 10 000 компаний, прошедших
  стоп-факторы; дефолты разыгрывает «скрытая» истинная функция риска, **отличная** от карты: другие веса, взаимодействие «молодой бизнес ×
  высокая нагрузка», шум. Seed фиксированы — цифры повторяются; CI проверяет, что отчёт совпадает с кодом.
- **Различающая способность:** AUC 0,716, Gini 0,431, KS 0,333 при доле дефолтов 5,4% — ранжирование рабочее [P24].
- **Точность:** доля дефолтов растёт от A к D (2,5 → 5,9 → 12,8 → 29,0%), но PD текущей шкалы ниже наблюдаемой (0,7 / 2,0 / 5,7 / 19,8%).
  Логистическая калибровка (odds 6,24 при 600 баллах, PDO 50,3) возвращает PD всех классов в 95%-интервал Уилсона; классы и пороги
  при этом не меняются.
- **Цена риска:** спред `PD для цены × LGD + 1,5 п.п.` покрывает ожидаемые потери при наблюдаемой доле дефолтов только в классе A.
- **Стабильность:** PSI 0,001 на новой выборке того же портфеля и 0,459 на портфеле в стрессе — мониторинг ловит сдвиг.
- **Факторы:** F4 (нагрузка) и F5 (просрочка) монотонны и сильнее всех по IV; F1–F3 немонотонны — кандидаты на объединение интервалов;
  F7 и F9 слабы по IV, но оставлены ради объяснимости и политики.

**Что делаем с выводами.** Синтетика проверяет методику и код, а не риск: «истину» задали мы сами. Поэтому политику по синтетике
не перекалибровываем. На данных банка тот же отчёт строится той же программой, а версия политики с новыми `pd_scale` и `pd_for_price`
включается через champion/challenger (04 §12). Методику держит тест `tests/test_scoring_validation.py`: AUC ≥ 0,68 и KS ≥ 0,25,
порядок классов, калибровка возвращает PD в интервалы, PSI тихий на том же портфеле и громкий в стрессе, сильные факторы монотонны.

## 8. Объяснения и путь к одобрению
Каждый фактор даёт вклад в баллах → три самых отрицательных вклада становятся причинами в «почему так» и рычагами K3.
У вклада — название фактора и направление (`plus`, `neutral`, `minus`, `unknown`); текст причины показываем только у факторов,
которые снижают балл: «бизнесу меньше года» рядом с бизнесом двух лет вводил бы в заблуждение.
В API: `GET /applications/{id}/explain` — вклад каждого фактора с интервалами карты и следующим порогом, PD и класс, ставка из частей,
лимит из ограничений, путь к одобрению; `GET /companies/{inn}/score` — то же до заявки (без согласия на КИ факторы полного отчёта БКИ
не считаются, 218-ФЗ ст. 6 ч. 9). Рычаги факторов и контрфакты — `app/domain/levers.py` (04 §7).
| Причина | Текст клиенту | Рычаг K3 |
|---|---|---|
| `SC_UNSTABLE_INFLOWS` | поступления сильно колеблются от месяца к месяцу | перевести обороты в банк; повторить через 3–6 мес. |
| `SC_DECLINING_INFLOWS` | поступления за 3 месяца снизились | повторить позже |
| `SC_HIGH_DEBT_LOAD` | платежи по кредитам занимают большую долю поступлений | меньше сумма; дольше срок |
| `SC_DELINQUENCY` | была просрочка по кредиту | повторить после N мес. без просрочек |
| `SC_CREDIT_HUNGER` | много запросов в БКИ за месяц | повторить через 30 дн. |
| `SC_YOUNG_BUSINESS` | бизнесу меньше года | повторить позже; поручитель |
| `SC_TAX_DEBT` | есть налоговая недоимка | погасить |
| `SC_LOSS` | убыток по отчётности | поручитель или залог |
| `SC_LOW_BANK_SHARE` | малая доля оборотов через банк | перевести обороты |

## 9. Реализация и путь роста
- Карта — YAML в версии политики (бины, баллы, пороги, шкала), расчёт — чистая функция `score(facts, segment) → {score, pd, class, contributions[]}`.
- Тесты: табличные по бинам и границам; свойства (рост поступлений не снижает балл, просрочка не повышает); golden по сценариям S и R.
- Сделано: карта — `app/domain/scoring.py`, рычаги и путь к одобрению — `app/domain/levers.py`, отчёт проверки — `qa/scoring.py`.
- Путь роста (финал): тот же порт `RiskModel` с ML-моделью (градиентный бустинг с монотонными ограничениями и вкладами признаков), обученной на синтетике или открытых данных из `refs/scoring/`;
  в решение идёт только с объяснением вкладов и после той же валидации §7.
