# 08. Демо: промежуточный этап «Кто я» и песочница мира

Ground truth по демо-режиму. Схема — **S0**. Работает только при `DEMO_MODE=true`; в обычной сборке эндпоинты песочницы не регистрируются.

## 1. Зачем
Проверяющему не нужно заводить «триллион» пользователей и компаний. Есть **один демо-пользователь** и **конфигуратор мира**: кто я, какие у меня компании,
какие у меня в них роли-сущности, какой у компаний профиль и как ведут себя внешние системы. Песочница **пишет только в моки** (WireMock и демо-данные банка),
логику не трогает. Дальше продукт работает как в бою: ходит в «реестры» по HTTP, разбирает ответы реальных форматов, считает права и решения.
Система не знает, что её тестируют, — поэтому демо честное.

## 2. Поток (страница S0)
1. **Вход в демо** → экран «Кто я сегодня»: выбрать пресет (S1–S9, R1–R13, N1–N17) или собрать персону.
2. **Проверка спеки:** ИНН с контрольной суммой по алгоритму ФНС, связи не противоречат закону (например, у ИП нет участников), доли ≤ 100%. Ошибки — подсказками у полей.
3. **Материализация мира:** шаблоны ответов по спецификациям (ЕГРЮЛ 4.06, XSD ФНС, ГИР БО, ЦБ v3.4, МЧД) заполняются из спеки и ставятся в WireMock;
   демо-данные банка (персона, доступы ДБО, устав, транзакции) пишутся в мок ядра. Транзакции строит генератор с фиксированным seed: профиль оборотов (стабильные, сезонные, падающие),
   регулярные платежи, налоги и зарплата по календарю (K1), при желании — кассовый разрыв на заданную дату.
4. **`registry.changed`** по каждому ИНН → воркер обновляет снапшоты → `parties` пересчитывает права с объяснением и нормой.
5. **Войти как эта персона** (демо-JWT) → кабинет: переключатель компаний с правами, главная, «Банк заметил». Или **войти как кредитный специалист** → очередь и досье.
6. **В любой момент:** событие мира, отказ интеграции, перемотка времени, сброс — без перезапуска.

## 3. Спека персоны (пример — пресет R8 + K1)
```json
{
  "preset": "R8",
  "person": { "fio": "Иванов Иван Иванович", "inn": "770000000001" },
  "companies": [
    { "name": "ООО «Северный Хлеб»", "inn": "7700000001", "opf": "LLC", "okved": "10.71", "registeredMonthsAgo": 40,
      "links": [ { "type": "EIO", "mode": "independent" } ],
      "participants": [ { "person": "self", "share": 60 }, { "fio": "Сидоров Пётр", "share": 40 } ],
      "profile": { "assetsTotal": "42000000", "turnover": "stable", "monthlyInflow": "3500000", "taxDebt": "0" },
      "flags": [], "charter": { "limits": [], "decisionMethod": "notary" },
      "signals": { "cashGap": { "inDays": 12, "amount": "340000" } } },
    { "name": "ООО «Альфа-Трейд»", "inn": "7700000002", "opf": "LLC", "links": [ { "type": "BANK_ACCESS", "level": "prepare" } ] },
    { "name": "ООО «Склад-Логистик»", "inn": "7700000003", "opf": "LLC", "links": [ { "type": "PARTICIPANT", "share": 40 } ] }
  ],
  "integrations": { "bki": "ok", "egrul": "ok", "mchd": "ok" }
}
```
Типы связей: `EIO` (`independent` | `joint`), `PARTICIPANT` (доля), `POA` (`paper` | `mchd`, статус `ACTIVE` | `EXPIRED` | `REVOKED` | `SUSPENDED`, полномочия, срок), `BANK_ACCESS` (`view` | `prepare`).
Флаги компании и лиц: недостоверность сведений, дисквалификация, банкротство, ликвидация, недоимка, «ЗАО» в ЕГРЮЛ, ограничения устава.

## 4. Пресеты
| Группа | Пресеты | Что показывают |
|---|---|---|
| Продукт | S1–S9 | основной путь, контрпредложение, отказ, ручное рассмотрение, таймеры, K1–K2, другой продукт, K5 |
| Роли и право | R1–R13 | права из сущностей, корпоративные одобрения, МЧД, совместные директора, поручитель, человек в трёх компаниях, смена директора на лету, «ЗАО» |
| Отказы | N1–N17 | поведение продукта при сбоях источников, нашем сбое и событиях мира (07 §6) |

## 5. События мира (`POST /sandbox/events`)
`egrul.director_changed` · `egrul.participant_changed` · `egrul.unreliable_flag` · `mchd.revoked | suspended | expired` · `fns.tax_debt_appeared | paid` ·
`legal.bankruptcy_started` · `approval.decided (yes | no)` · `bank.inflow_delayed` (сдвигает поступление → K1 видит разрыв) · `eis.contract_signed` (K5) ·
`time.advance (дни)` — сдвиг часов песочницы, чтобы показать истечение сроков и «28-е число» без ожидания.
Каждое событие меняет только данные моков → `registry.changed` → продукт реагирует сам (пересчёт прав, задачи, пересмотр).

## 6. Отказы интеграций (`POST /sandbox/faults`)
| Поле | Значения |
|---|---|
| Источник | ЕГРЮЛ, ЕГРИП, ФНС, ГИР БО, БКИ, МЧД, юр. проверки, банк, АБС, ЕИС |
| Режим | медленно · таймаут · 5xx · 429 · обрыв · пустой ответ · мусор · 404 · дрейф схемы · флаппинг (N ошибок, потом успех) · обрыв после выдачи (АБС) |
| Скоуп | все ИНН или компания из персоны |
| Длительность | до отмены · N вызовов · M минут |
Реализация — стабы WireMock с приоритетом 1 и метаданными `createdBy: sandbox` (07 §7). Плюс `POST /sandbox/worker/pause | resume` — наш собственный сбой.
Панель показывает активные отказы, состояние breaker по источникам и журнал вызовов WireMock.

## 7. «Почему так?»
Панель на каждом экране: какие правила сработали, на каких фактах (с источником и датой) и по какой норме. Это та же трасса, что в досье аналитика (04 §4).

## 8. Сброс
`POST /sandbox/reset`: удалить демо-данные песочницы и заявки демо-персоны, `POST /__admin/mappings/reset` и `POST /__admin/scenarios/reset` в WireMock, сбросить часы.

Хранение: спека персоны и часы — в `kv`, отказы — метаданные стабов WireMock; отдельных таблиц у песочницы нет.

## 9. Безопасность демо-режима
Только при `DEMO_MODE=true`; красная плашка «Демо-режим: данные реестров смоделированы»; все действия песочницы в аудите с пометкой `sandbox`;
песочница не имеет доступа к движку решения и state machine — только к мокам и демо-данным банка.
