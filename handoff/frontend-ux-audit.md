# Фронт Fino: разбор живого стенда и что переделать

Стенд — `main` @ `57ca92f` (после PR #3), общий compose из `infra/`, http://localhost:8080, 23.10.2026.
Смотрели в Chromium на ширине 1440 и 390 px, в русской локали. Все запросы к `/api` записаны как во вкладке Network (F12):
тела ответов, время, повторы. В базе лежали заявки от прошлых тестовых прогонов, поэтому очередь банка была не пустой.
На чистом стенде её не будет.

Что прошли:
- вход как ИП Смирнова (S7): «закрыть разрыв в 1 клик» → заявка → оферта → подпись → выдача;
- «Подобрать кредит»;
- отказ с путём к одобрению (S4) и встречное предложение (S3);
- своя компания — ООО из трёх участников: крупная сделка, голосование двух участников, оферта;
- рабочее место банка: очередь, досье, метрики, аудит;
- пользователь с тремя компаниями (R8);
- управление миром и сценарии по ролям;
- мобильная ширина и страница 404.

Итог. Ядро работает и быстро отвечает: решение меньше чем за секунду, API — меньше 100 мс. Путь до выдачи проходит без ошибок.
Проблемы в трёх местах:
- вход и обвязка симулятора;
- данные, которые не доходят до следующих экранов: выданный кредит не меняет главную;
- тексты, написанные языком аналитика, а не предпринимателя.

## Целевой путь

1. **Главная** — страница о продукте: что сервис даёт предпринимателю и какие есть продукты (ставка «от», суммы, сроки —
   `GET /api/v1/catalog/products`). Кнопка «Войти».
2. **Вход** — условный: выбрать пользователя из списка или ввести ID или ИНН (`POST /api/v1/auth/login {"login": "s7"}` уже есть).
3. **Выбор пользователя** — простым языком: кто это и что за бизнес. Без кодов и сценариев. «Создать свою компанию» — первым
   блоком, заметно.
4. **Кабинет** — главная, подбор, заявки. У сотрудника банка — очередь, все заявки, метрики.
5. **Инструменты симулятора** — время, события в реестрах, отказы источников, пауза, сброс. Сценарии по ролям — на отдельной
   странице вне кабинета клиента, со ссылкой из README. Сценарии описаны в документации (`docs/15_roles.md`).

## Сеть (F12)

- **Скорость.** API быстрое: почти всё отвечает меньше чем за 100 мс. Вход — 300–550 мс (бэк собирает данные компании),
  решение движка — меньше секунды.
- **Лишние запросы:**
  - каждое событие из потока (SSE) заново запрашивает заявку и историю — после подписи это 11 запросов за 100 мс;
  - `explain` при этом запрашивается трижды, хотя после оферты решение уже не меняется;
  - `/demo-personas/{inn}` запрашивается дважды на каждой странице, досье — тоже дважды;
  - на страницах банка грузится весь список пользователей `/sandbox/personas` (13–15 КБ).

  → Обновлять по данным события, `explain` — только при смене решения, повторные запросы склеивать (дебаунс). **[фронт]**
- **Консоль чистая**, если не считать ожидаемых 404 на несуществующей заявке.

## Что меняем на бэке (наша часть)

Полный лог изменений будет, когда закончим. Пока список, чтобы фронт знал, что придёт:
- **Карточки входа.** Человек, компания, роль и пара фраз о бизнесе. Без кодов, сценариев, исходов и дублей (`n1` и `n2` из
  списка уходят). ID для входа прежние. Старые поля `GET /sandbox/personas` останутся, но с нейтральным текстом, плюс новые поля.
- **Время.** Одна дата мира для прогноза, сроков и отметок времени. Таймеры — реальные, в днях; перемотка — в инструментах.
- **Выданный кредит.** Учитывается в прогнозе (лимит овердрафта или платёж срочного кредита), в предодобрении (без повторного
  предложения) и в сводке главной.
- **Продукты.** Для вошедшей компании — персональные ставки и доступность продуктов, у недоступных — причина. Пустое
  предодобрение — с причиной и путём.
- **Подбор от задачи.** Задача → варианты с расчётом. Заявку можно подать без продукта.
- **Права.** Смотреть счёт — только по ДБО. Участник ООО — только голосует.
- **Объяснения.**
  - у события есть автор: имя и роль;
  - у пути к одобрению есть тип по исходу;
  - лимиты показаны с суммами;
  - у причин есть подробности (кто с кем расходится).
- **Мелочи данных.** ЕГРИП для ИП в профиле, короткие названия компаний в `/me`, номер кредитного договора от АБС вместо UUID.
- **Овердрафт.** Формулировка «лимит подключён», расчёт цены по фактическому использованию. Сравнение способов погашения — только
  для срочных кредитов, рекомендация с учётом переплаты.
- **Банк.** Реестр всех заявок.
- **Конструктор.**
  - ввод простыми вопросами;
  - отрасль из списка;
  - устройство компании и люди со ссылками на нормы;
  - особенности описаны фактами.
- **Генерация.** Люди, доли, налоговый режим, профили отраслей.
