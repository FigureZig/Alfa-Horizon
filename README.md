# Alfa Horizon

Кредитный кабинет для малого бизнеса. Сделали на Альфа Хак 2026, трек ММБ. В интерфейсе продукт называется «Fino Бизнес», банк — «Fino Банк».

Обычно, чтобы взять кредит, предприниматель заполняет длинную анкету и ждёт ответа несколько дней. У нас наоборот: человек говорит, зачем ему деньги, а банк сам собирает данные о компании из реестров, принимает решение за секунды и объясняет его простыми словами. А если денег скоро не хватит, кабинет заметит это заранее и сразу предложит, как закрыть разрыв.

Все компании и люди в демо вымышленные. Реестры (ФНС, ГИР БО, кредитная история и т. д.) заменены моками в тех же форматах, что у настоящих источников.

## Как запустить

Нужен только Docker (Docker Desktop или Docker Engine с Compose версии 2.20 и новее). Ничего ставить отдельно не нужно.

```bash
git clone <адрес репозитория>
cd Alfa-Horizon/infra
docker compose up --build
```

Первая сборка занимает несколько минут. Когда в логах перестанут бежать строки, откройте:

| Адрес | Что там |
|---|---|
| http://localhost:8080 | сам кабинет — начинать отсюда |
| http://localhost:8000/api/docs | документация API (Swagger), там же можно дёргать ручки |
| http://localhost:8000/api/redoc | та же документация в виде ReDoc |
| http://localhost:8081/__admin | WireMock — моки реестров, если интересно, что «отвечает» ФНС |
| `localhost:55432` | PostgreSQL (логин и пароль `app` / `app`, база `credit`) |

Чтобы запустить в фоне, добавьте `-d`: `docker compose up --build -d`.

Остановить: `docker compose down`. Остановить и стереть базу (начать с нуля): `docker compose down -v`.

Файл `.env` для запуска не нужен — все настройки по умолчанию уже прописаны. Если хочется что-то поменять, шаблон лежит в `backend/.env.example`.

### Если что-то пошло не так

- **Порт занят.** Стенд использует 8080, 8000, 8081 и 55432. Освободите порт или поменяйте его: например, фронт можно поднять на другом порту через `WEB_PORT=3000 docker compose up --build`.
- **После `git pull` всё выглядит по-старому.** Пересоберите образы: `docker compose up --build`. Если смотрите в браузере — обновите страницу без кэша (Cmd+Shift+R / Ctrl+Shift+R).
- **Сразу после входа крутятся заглушки.** Это нормально: банк в этот момент собирает данные о компании из реестров. Через пару секунд всё появится само.
- **Данные «замусорились» после прошлых прогонов.** Нажмите «Как проверить» → «Мир» → «Сбросить мир». Если нужно совсем с чистого листа — `docker compose down -v` и запустить заново.

## Первые пять минут

1. Откройте http://localhost:8080 и нажмите «Войти».
2. Пароль не нужен. Дальше три пути:
   - **«Пройти готовый сценарий»** — приложение проведёт по шагам: подскажет, кем войти, что нажать и какой статус должен получиться. Плашка внизу справа показывает, на каком вы шаге, и открывает следующий. Это самый быстрый способ всё увидеть, 2–3 минуты на сценарий.
   - **«Своя компания»** — опишите свой бизнес за минуту и посмотрите, что предложит банк.
   - **Войти самому** — в блоке «Или войдите сами» выберите компанию и человека, откроется его кабинет.

   При первом входе покажется короткая подсказка, как пройти сценарий. Закрыли и забыли — её можно открыть снова по ссылке «Как пройти сценарий» на экране входа.
3. Чтобы посмотреть ту же заявку глазами другого человека (например, директора после бухгалтера или специалиста банка), нажмите «Сменить» в шапке и войдите другим пользователем. Заявки при этом никуда не пропадают.
4. В правом нижнем углу есть кнопка «Как проверить». Там все сценарии, управление «миром» (время, события в реестрах, поломки источников) и короткие пояснения, где смотреть каждое решение продукта.

Если хотите начать с чего-то простого — войдите как **Анна Смирнова** (ИП, кофейня): у неё есть прогноз денег на счёте, подбор кредита и несколько заявок в разных статусах. Для стороны банка — **Мария Соколова**, кредитный специалист.

## Что умеет

### Для клиента

- **Прогноз денег на 30 дней.** На главной видно, сколько денег на счёте сейчас и что будет дальше: какие платежи спишутся, что поступит и в какой день может не хватить. Если намечается кассовый разрыв, кабинет покажет точную дату, сумму и сколько будет стоить его закрыть.
- **Подбор кредита от задачи.** Не нужно разбираться в продуктах банка. Человек выбирает, на что нужны деньги («закрыть кассовый разрыв», «закупить товар», «купить оборудование»…), и видит, что банк готов дать именно ему: сумму, личную ставку и платёж. Если какой-то продукт не подходит, написано почему.
- **Заявка без анкеты.** Данные о компании банк берёт сам. Решение приходит через пару секунд, и рядом всегда есть блок «Почему такое решение»: из чего сложилась ставка, какие факторы повлияли, а при отказе — что сделать, чтобы одобрили.
- **Весь путь заявки в одном месте.** Предложение банка, подпись, выдача денег, ответы на запросы банка, история действий с именами — всё видно в карточке заявки. Список заявок разбит на «Нужно ваше действие», «В работе у банка» и «Завершённые».
- **Разные роли внутри компании.** Бухгалтер может подготовить заявку, но подписать её может только директор. Представитель по доверенности (МЧД) подписывает сам, пока доверенность действует. Если сделка крупная, участники ООО голосуют по своим долям. Права каждого считаются из реестров, а не задаются руками.
- **Своя компания.** Можно ответить на несколько вопросов о своём бизнесе (чем занимаетесь, кто директор, есть ли партнёры, как платят клиенты) и посмотреть, что банк предложит такой компании. Каждый человек из неё сможет войти отдельно.

### Для банка

- **Очередь исключений.** Специалисту попадают только те заявки, которые система не смогла решить сама: например, расходятся данные реестров или сумма выше порога. Для каждой написано, почему нужен человек и сколько осталось времени.
- **Досье заявки.** Факты о компании, подсказка системы и решение специалиста: одобрить, отказать, запросить документы.
- **Второй ключ.** Если специалист одобряет сумму выше своих полномочий (больше 15 млн ₽), решение уходит на подтверждение риск-менеджеру.
- **Все заявки и метрики.** Полный реестр заявок, включая решённые автоматически, и статистика по тому, как работает конвейер.

### Для проверяющих (симулятор)

- **Готовые сценарии** со сменой ролей — по шагам, с кнопками «Войти как …».
- **Часы мира.** Можно перемотать время вперёд, чтобы истекли сроки предложения или подписи. Стенд «живёт» с 21 октября 2026 года.
- **События в реестрах.** Например, сменился директор в ЕГРЮЛ или погашена налоговая недоимка — банк сам пересмотрит незавершённые заявки.
- **Поломки источников.** Можно «уронить» кредитное бюро или другой реестр и посмотреть, как система себя ведёт.
- **Пауза обработки заявок.** Заявки останавливаются в текущем статусе, всё остальное работает. Удобно, чтобы спокойно рассмотреть промежуточный шаг.

Всё это меняется на лету, без перезапуска.

## Деплой на сервер

Стенд разворачивается за [Caddy](https://caddyserver.com): он сам получает и продлевает HTTPS-сертификат Let's Encrypt и отдаёт кабинет на домене. По умолчанию это **https://alfahorizon.duckdns.org**.

Что нужно на сервере:

- Docker с Compose 2.24 или новее;
- открытые порты 80 и 443: через 80 Let's Encrypt проверяет домен, на 443 работает сайт;
- DNS-запись домена указывает на IP сервера. Для DuckDNS IP обновляется так: `curl "https://www.duckdns.org/update?domains=alfahorizon&token=<токен DuckDNS>&ip="` (пустой `ip` — взять адрес, с которого пришёл запрос).

```bash
cd Alfa-Horizon/infra
cp .env.example .env              # впишите DEMO_TOKEN_SECRET: openssl rand -hex 32
docker compose -f docker-compose.yml -f docker-compose.prod.yml up --build -d
```

| Адрес | Что там |
|---|---|
| https://alfahorizon.duckdns.org | кабинет |
| https://alfahorizon.duckdns.org/api/docs | Swagger |
| https://alfahorizon.duckdns.org/api/redoc | ReDoc |

Наружу смотрят только 80 и 443. Порт фронта 8080 закрыт, а API, WireMock и PostgreSQL слушают только `127.0.0.1` — до них можно дойти через SSH-туннель, например `ssh -L 8000:localhost:8000 <сервер>`.

Другой домен — `DOMAIN` в `infra/.env`. Без `DEMO_TOKEN_SECRET` стенд не запустится: секрет по умолчанию из репозитория на сервере не годится. Сертификаты лежат в томе `caddy_data` — не удаляйте его, иначе Caddy будет запрашивать их заново и может упереться в лимиты Let's Encrypt. Обновить стенд после `git pull` — та же команда `up --build -d`.

## Если хотите запускать по частям (для разработки)

Обычно это не нужно — `docker compose up` в `infra/` поднимает всё сразу. Но если вы правите код и не хотите каждый раз пересобирать образы:

**Бэкенд** (нужны Python 3.13+ и [uv](https://docs.astral.sh/uv/)):

```bash
cd backend
cp .env.example .env
docker compose up -d postgres wiremock      # база и моки — в Docker
uv sync
uv run --env-file .env python -m app.migrate
uv run --env-file .env uvicorn app.main:app --reload --port 8000
uv run --env-file .env python -m app.worker  # в отдельном терминале
```

Только бэкенд целиком в Docker: `cd backend && docker compose up --build`.

**Фронтенд** (нужны Node.js 20.11.1 и pnpm 10):

```bash
cd frontend
pnpm install
cp .env.example .env
pnpm dev                                    # http://localhost:5173
```

Фронт в режиме разработки ходит в API через прокси на `http://localhost:8000`, так что бэкенд должен быть запущен.

После каждого `git pull` стоит снова выполнить `pnpm install` и `uv sync` — если кто-то добавил зависимость, без этого проект не соберётся.

**Проверки:**

```bash
cd backend && uv run ruff check . && uv run pytest     # бэкенд: линтер и тесты
cd backend && uv run pytest -m e2e                     # сквозные тесты, нужны postgres и wiremock
cd frontend && pnpm lint && pnpm build                 # фронт: линтер и сборка
```

Ещё есть коллекция для Postman — [`docs/api/postman_collection.json`](docs/api/postman_collection.json). Её можно прогнать целиком через Collection Runner или `newman`: она проходит вход, кабинет, заявку до выдачи и все сценарии ролей.
