# Alfa Horizon

Умный кредитный кабинет предпринимателя — Альфа Хак 2026, трек ММБ. Предприниматель описывает задачу бизнеса, а не заполняет анкету:
банк сам собирает данные из реестров, решает как опытный кредитный эксперт, объясняет решение и предлагает деньги раньше, чем они понадобились.

## Запуск

```bash
cd infra
docker compose up --build        # весь стенд: фронт, API, worker, Postgres, WireMock (Docker Compose ≥ 2.20)
```

| Адрес | Что |
|---|---|
| http://localhost:8080 | фронт (nginx отдаёт сборку и проксирует `/api` на бэкенд) |
| http://localhost:8000/api/docs | API; контракт — [`docs/api/openapi.json`](docs/api/openapi.json), соглашения — [`docs/api/README.md`](docs/api/README.md) |
| http://localhost:8081/__admin | WireMock: моки реестров, БКИ и банка в реальных форматах |
| `localhost:55432` | PostgreSQL |

Только бэкенд — `cd backend && docker compose up --build`. Настройки — `backend/.env` (шаблон `backend/.env.example`;
без файла подставятся значения по умолчанию).
Все компании и люди вымышленные; мир симулятора — [`backend/seed/personas.yaml`](backend/seed/personas.yaml).

## Как проверить

1. Поднимите стенд (выше) и откройте http://localhost:8080 — или документацию API: Swagger http://localhost:8000/api/docs
   (кнопка **Authorize**), ReDoc http://localhost:8000/api/redoc.
2. Войдите пользователем: выберите карточку или введите ID — `POST /api/v1/auth/login {"login": "s7"}`. Перелогин между ролями —
   тот же вход другим ID; права и кнопки (`available_actions`) пересчитываются, заявки остаются.
3. Пройдите сценарии. Каждый — смена ролей с проверкой статуса после шага; пошаговый гид (кем войти, что нажать, какой статус
   ждать) отдаёт сам продукт — `GET /api/v1/sandbox/scenarios`, подробно — [`docs/15_roles.md`](docs/15_roles.md) §4:

| Сценарий | Кто по очереди | Чем заканчивается |
|---|---|---|
| Кассовый разрыв и кредит в 1 клик | `s7` | прогноз видит разрыв 28.10 → овердрафт → оферта → подпись → `ISSUED` |
| Крупная сделка | `s2` → участники `u-li`, `u-morozov` → `s2` | голосование по долям (14-ФЗ ст. 46): «за» — выдача, «против» — `WITHDRAWN` |
| Бухгалтер готовит, директор подписывает | `r8` → `r12` | подготовка без права подписи (403) → подпись директора → `ISSUED` |
| Второй ключ | `u-fomin` → `bank` → `risk` → `u-nikitin` | специалист одобряет 18 млн ₽ выше своего порога → риск-менеджер подтверждает → выдача |
| Дозапрос специалиста | `s5` → `bank` → `s5` → `bank` | запрос документов → ответ → одобрение в пределах полномочий |
| Смена директора во время подписи | `r12` → событие в ЕГРЮЛ → `u-novikova` | подпись остановлена, прежний директор — 403, подписывает новый |
| Подпись по доверенности (МЧД) | `u-kuznetsova` → (отзыв МЧД) → `s3` | представитель подписывает сам по действующей МЧД; после отзыва — 403, подписывает директор |
| Отказ и путь к одобрению | `s4` → событие «недоимка погашена» → `s4` | отказ со стоп-фактором и подсказкой → повторная заявка → `OFFERED` |

4. Своя компания — `POST /api/v1/sandbox/personas` с флагами (недоимка, просрочка, крупная сделка, БКИ не отвечает…): каталог —
   `GET /api/v1/sandbox/persona-options`, каждый флаг меняет решение.
5. Всё сразу автоматически: коллекция [`docs/api/postman_collection.json`](docs/api/postman_collection.json) в Postman (Collection
   Runner) или `newman` — проходит вход, кабинет, заявку до выдачи и все сценарии ролей; сквозные тесты — `cd backend && uv run pytest -m e2e`.

## Состояние

**Готово.** Вход пользователем симулятора и перелогин между ролями: директор, бухгалтер с правом подготовки, участник ООО, кредитный
специалист, риск-менеджер; права «человек × компания» считаются из ЕГРЮЛ/ЕГРИП и ДБО. Кабинет компании: прогноз остатка на 30 дней
и кассовый разрыв (K1), предодобренные продукты и предложение, которое закрывает разрыв (K2), кредитное здоровье с рычагами,
выбор графика: фиксированный или доля поступлений со стресс-тестом на худших месяцах (K4), сигнал о новом госконтракте
с кредитом на исполнение (K5).
Данные из реестров (моки в форматах ФНС, ГИР БО и ЦБ) → факты → решение: стоп-факторы, продукт по отрасли, скоринг, ставка, лимит,
контрпредложение, полномочия, «почему так» и путь к одобрению (K3). Заявка целиком: оферта, подпись (совместные директора), голосование
участников за крупную сделку, подпись представителя по МЧД, финальная проверка и выдача в АБС с ключом идемпотентности, дозапрос, решение специалиста и второй ключ
риск-менеджера выше его полномочий, отзыв, пересмотр при событиях мира (в том числе смена директора во время подписи), сроки.
Симулятор: вход по ID, своя компания с флагами, которые меняют решение, отказы источников, события мира и часы на лету без перезапуска.
Живой таймлайн заявки (SSE). Документация API — Swagger и ReDoc со схемами всех ответов.

**Проверено.** Граф статусов, pairwise-компании и инварианты чисел, 16 сквозных прогонов всех переходов и 9 сценариев со сменой ролей
на живом стенде ([`docs/test-scenarios.md`](docs/test-scenarios.md), [`docs/15_roles.md`](docs/15_roles.md)); скоринговая карта на
синтетическом портфеле — Gini, KS, калибровка, PSI ([`docs/scoring_validation.md`](docs/scoring_validation.md)).

**Дальше:** несколько компаний у своего пользователя, КЭП и криптопроверка МЧД вместо ПЭП в ДБО.
